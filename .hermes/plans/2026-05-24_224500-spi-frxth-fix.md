# SPI 驱动根因诊断 + 修复方案

## 问题描述

`wait_for_sample()` 挂死。SPIDevice 重写后的 `_do_transfer()` 卡在 RXNE 等待循环。

## 根因分析

通过逐行审查 `SPIDevice.cpp`，发现 **`SPIBus::start_peripheral()` 只配置了 CR1，完全没有配置 CR2 寄存器。**

```cpp
void SPIBus::start_peripheral(void)
{
    uint32_t cr1 = SPI_CR1_MSTR | SPI_CR1_SSM | SPI_CR1_SSI | SPI_CR1_SPE | current_br;
    if (cfg.mode & 0x01) cr1 |= SPI_CR1_CPHA;
    if (cfg.mode & 0x02) cr1 |= SPI_CR1_CPOL;
    spi->CR1 = cr1;
    // ← CR2 从未配置！
    ...
}
```

### STM32F7 SPI FIFO 机制

STM32F7 的 SPI 有一个 **4 级深度的 FIFO**。`FRXTH`(CR2 bit12) 控制 RXNE 触发阈值：

| FRXTH | 8-bit RXNE 触发条件 | 适用于 |
|:-----:|:------------------:|:------:|
| **0 (复位默认)** | **FIFO ≥ 4 字节** | DMA/批量传输 |
| **1** | **FIFO ≥ 1 字节** | 轮询/单字节 |

**问题**：默认 FRXTH=0，RXNE 需要 FIFO 积累 4 字节才置位。但 `_do_transfer()` 是**逐字节轮询**模式——发 1 字节→等 RXNE（卡死！因为 FIFO 只有 1 字节，RXNE 永远不会置位）。

### ChibiOS 参考

ChibiOS `spi_lld_start()` (hal_spi_lld.c:260-280) 中明确配置了 CR2：
```c
spi->CR2 = SPI_CR2_FRXTH;   // 8-bit 轮询传输必备
```

## 修复方案

### 改动
**文件**：`libraries/AP_HAL_RTT/SPIDevice.cpp`
**位置**：`SPIBus::start_peripheral()` (L221-234)

在 `spi->CR1 = cr1;` **之前** 添加一行：
```cpp
spi->CR2 = SPI_CR2_FRXTH;
```

### 完整修复后的 `start_peripheral()`
```cpp
void SPIBus::start_peripheral(void)
{
    if (spi_started) {
        return;
    }
    uint32_t cr1 = SPI_CR1_MSTR | SPI_CR1_SSM | SPI_CR1_SSI | SPI_CR1_SPE | current_br;
    if (cfg.mode & 0x01) cr1 |= SPI_CR1_CPHA;
    if (cfg.mode & 0x02) cr1 |= SPI_CR1_CPOL;
    spi->CR2 = SPI_CR2_FRXTH;   // ← 修复：使能 8-bit 单字节 RXNE
    spi->CR1 = cr1;
    __DSB();
    spi_started = true;
}
```

### 风险
- **极低**。FRXTH=1 是 8 位轮询模式的标配设置，ChibiOS、HAL、RT-Thread 原生 SPI 驱动全部如此。
- 不会影响 SPI2 的 FRAM（同样用 8 位轮询访问）或 SPI4 的 MS5611。

## 验证流程

1. 修改 SPIDevice.cpp（加一行）
2. `scons --v=ArduCopter --target=cuav_v5 -j$(nproc)` 编译
3. OpenOCD 烧录至 0x08008000
4. 复位运行，10s 后用 OpenOCD halt 读 debug 变量：
   - `mdw 0x20018fb4` → `main_loop_iterations > 0` ✅
   - `mdw 0x20018fa8` → `fast_loop_count > 0` ✅
5. 检查 MAVLink 心跳
