# USB DWC2 驱动移植规划 — ChibiOS LLD → RTT

> 作者：小马总（Orchestrator）
> 日期：2026-05-24
> 状态：规划草案

---

## 1. 问题

**当前 RTT 的 USB 使用 CherryUSB 作 USB 设备栈，但 DWC2 初始化 CSRSTDONE timeout，USB 无法通信（MAVLink 无心跳）。**

板级现象：
- USB CDC 可枚举（`1209:5741 Generic CUAVv5 RTT`）
- 但无任何数据流（MAVLink HEARTBEAT 一直没出来）
- 已知 root cause 是 DWC2 core reset 完成后 CSRSTDONE 不置位

## 2. 策略

**方案：ChibiOS USBv1 LLD 移植到 RTT**

和 ADC/SPI LLD 一样，提取 ChibiOS 已验证的 DWC2 驱动代码，适配 RTT。但与 ADC/SPI 不同，USB 驱动更复杂（~900行 LLD + 中断处理），且需要考虑上层接口。

### 2.1 ChibiOS USB 架构层次

```
USBDriver (上层 HAL)
    ↓
usb_lld_start() / usb_lld_epXxx()  ← LLD API
    ↓
DWC2 寄存器操作 (OTG_FS/HS)
```

### 2.2 RTT 对接层次

两种方案：

**方案 A（推荐）：ChibiOS USB LLD + CherryUSB 上层**
```
CherryUSB usbd_core / CDC ACM
    ↓ (适配层)
ChibiOS USBv1 LLD 移植 → drivers/hal_usb_lld_rtt.c
    ↓
DWC2 寄存器
```

**方案 B（更彻底）：完整 ChibiOS USB HAL + LLD**
```
USBDriver (ChibiOS HAL 移植)
    ↓
usb_lld_xxx() (ChibiOS USBv1 LLD)
    ↓
DWC2 寄存器
```
但需要同步移植 CDC ACM 类，工作量较大。

**推荐方案 A** — 底层替换核心 DWC2 初始化和数据传输，上层保留 CherryUSB 的 CDC ACM 实现，通过适配层对接。

## 4. 移植步骤

### Phase 1: 差异分析（ce-analogin 进行中 t_a053c2d1）

ce-analogin 正在对比 ChibiOS vs CherryUSB DWC2 初始化序列，找出 CSRSTDONE timeout 根因。如果只是简单的寄存器配置差异，打补丁比完整移植更快。

**如果根因是 1-2 个寄存器配置差异 → 只需打补丁到 CherryUSB usb_dc_dwc2.c**

**如果差异面较大（初始化顺序、中断处理、FIFO 分配）→ 执行 Phase 2 完整移植**

### Phase 2: ChibiOS USBv1 LLD 提取适配

#### Step 2.1 Core Reset 序列
```
ChibiOS usb_lld_start() L477-500:
  1. RCC 使能 OTG FS 时钟
  2. 复位 OTG (RCC reset)
  3. GAHBCFG 配置 (burst length, DMA)
  4. GRSTCTL 写 CSRST → 等待 CSRSTDONE
  5. DCTL 设 Soft Disconnect
  6. GINTMSK 设中断掩码
  7. FIFO 分配 (GRXFSIZ, GNPTXFSIZ, DIEPTXF)
  8. DAINT 使能端点中断
  9. DCTL 取消 Soft Disconnect
  → 适配: 删除 ChibiOS 的 osal 调用, 直接寄存器写
```

#### Step 2.2 Endpoint 配置
```
ChibiOS usb_lld_start_out() / usb_lld_start_in() L778-830:
  1. DOEPCTL 配置 OUT endpoint
  2. DIEPCTL 配置 IN endpoint
  3. 设置 MPSIZ、EPTYPE、TNCTRL
  → 适配: 改为 CherryUSB 回调可调用的函数
```

#### Step 2.3 数据传输
```
ChibiOS usb_lld_epXxx():
  - usb_lld_read_setup()           ← 读 SETUP 包
  - usb_lld_read_out()             ← 读 OUT 数据
  - usb_lld_write_in()             ← 写 IN 数据
  - usb_lld_flush_ep()             ← 冲洗端点
  → 适配: 改为函数指针供 CherryUSB 调用
```

#### Step 2.4 中断处理
```
ChibiOS USB ISR:
  - GINTSTS 读取中断状态
  - 路由到：OTG 事件 / SOF / EP 事件 / 复位 / 断开
  - EP 事件：DAINT 解析 → IN/OUT 分发
  → 适配: 保留 CherryUSB 的 ISR 入口，内部调用 ChibiOS LLD 逻辑
```

### Phase 3: CherryUSB 适配层

创建 `CherryUSB_glue.c`，将 ChibiOS LLD 的函数包装为 CherryUSB 的 `usbd_dc_lowlevel_xxx()` 接口：

```c
// CherryUSB 期望的接口（在 usb_dc.h 中定义）
int usbd_init(void);          → 调用 chibios_usb_lld_init()
int usbd_deinit(void);
int usbd_ep_open(usbd_endpoint_t *ep);    → 调用 chibios_ep_open()
int usbd_ep_close(usbd_endpoint_t *ep);
int usbd_ep_set_stall(usbd_endpoint_t *ep);
int usbd_ep_clear_stall(usbd_endpoint_t *ep);
int usbd_ep_write(uint8_t ep, uint8_t *data, uint32_t len);  → 调用 chibios_ep_write()
int usbd_ep_read(uint8_t ep, uint8_t *data, uint32_t len);
```

### Phase 4: 编译 + 烧录验证

1. 完整编译：`scons --v=ArduCopter --target=cuav-v5 -j$(nproc)`
2. 烧录：OpenOCD program 0x08008000 + verify
3. MAVLink 验证：pymavlink wait_heartbeat()

## 5. 预期差异处理（相对 ADC/SPI LLD）

| 项目 | ADC/SPI LLD | USB LLD |
|------|-------------|---------|
| 行数 | 190-269 | ~400-500（核心部分） |
| OSAL 依赖 | 无 | 少量（`chSysLock` 关键区保护） |
| 中断 | 无（轮询模式） | **必需**（中断驱动） |
| DMA | 无 | 无（DWC2 用 FIFO 不是 DMA） |
| 上层接口 | 自定义简单 API | CherryUSB `usbd_dc_xxx()` 标准接口 |
| 时钟配置 | RCC APB2 | RCC AHB + OTG FS 时钟 |

## 6. 风险与权衡

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| CherryUSB 上层耦合深（依赖 usbd_core） | 中 | 高 | 只替换 port/dwc2 层，不动 core |
| USB 中断优先级冲突 | 低 | 高 | 参考 ChibiOS 中断优先级设置 |
| DWC2 FIFO 分配不匹配 | 中 | 中 | 按 ChibiOS FIFO 大小重新分配 |
| 适配层接口不完整遗漏某些回调 | 中 | 中 | 逐个检查 CherryUSB usbd_dc.h 所有接口 |

## 7. 验证矩阵

| 检查项 | 方法 | 期望值 |
|--------|------|--------|
| DWC2 CSRSTDONE | OpenOCD 读 GINTSTS | 不复位卡死 |
| USB enum | `lsusb` | `1209:5741` |
| CDC ACM 数据 | pymavlink | HEARTBEAT 1Hz |
| 无 HardFault | `mdw 0xe000ed2c` | 0x00000000 |
| 批量传输 | mavproxy | RAW_IMU 10Hz |
